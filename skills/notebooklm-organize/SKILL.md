# NotebookLM 整理(一括リネーム)

目的: 全ノートブックのタイトルを命名規則にそろえ、一覧で探しやすくする。
成果物: 全ノートブックが命名規則どおりに変わり、作業フォルダに対照表(`rename-proposal.md` / `mapping.json`)が残り、読み取りで反映を確かめた状態。

> **2026-07 の注意**: Google が NotebookLM を Gemini Notebook に刷新した(`notebook.google.com`)。
> 以後、CLI の `notebooklm rename` は `success: true` を返すのに**名前が変わらない**(notebooklm-py 0.7.3 で確認)。
> 一覧取得の `notebooklm list --json` は使える。名前変更は下の「ブラウザ経由のリネーム」で行う。

## 命名規則

```
<絵文字>【カテゴリ】タイトル
```

- **絵文字**: カテゴリーごとに固定(下表)
- **【】**: 全角のすみ付きかっこ
- **タイトル本体**: 日本語推奨。英字が混ざってよい
- **長さ**: 全体で **22 表示カラム以内**(全角=2 / 半角=1 / 絵文字=2 で数える)
- **禁止**: タイトル本体に `_`(アンダースコア)。カード表示で改行されず「...」で切れる。区切りは半角スペースか `・`
- **並び順を固定したいシリーズは番号を付ける**: `📢【SNS】0 運用戦略` `📢【SNS】1 X戦略`

### カテゴリーの例(利用者に合わせて作り替える)

| カテゴリー | 絵文字 | 用途の例 |
|---|---|---|
| 【AI】 | 🤖 | AI ツール全般・自動化 |
| 【Claude】 | 🧠 | Claude / Claude Code 関連 |
| 【講座】 | 🎓 | オンライン講座・セミナー |
| 【SNS】 | 📢 | SNS 運用(番号付き) |
| 【マーケ】 | 💹 | マーケティング・収益化 |
| 【仕事】 | 🏢 | 本業の資料・マニュアル |
| 【学習】 | 📚 | 本・学習リソース |
| 【その他】 | 📦 | 分類できないもの・テスト |

初回は一覧を見てからカテゴリー案を利用者に提示し、合意してから使う。

## 進め方

1. `notebooklm list --json` で全件を取り、`created_at` の古い順に並べる
2. タイトル(必要なら中身)からカテゴリーを推定し、新タイトル案を作る
3. 作業フォルダに `rename-proposal.md`(旧→新の対照表、カテゴリー別件数)を書き、**利用者に見せて承認を待つ。承認前に変更しない**
4. 承認後、実行用の `mapping.json` を作る

   ```json
   {
     "renames": [{"id": "<notebook_id>", "new": "🏢【仕事】操作マニュアル"}],
     "deletes": []
   }
   ```

   削除候補がある時は、**削除だけ別に改めて確認を取る**
5. 下の「ブラウザ経由のリネーム」で実行する
6. 「検証」で反映を確かめ、結果を報告する

## ブラウザ経由のリネーム

ブラウザ操作ツール(Claude in Chrome など、ページ上で JavaScript を実行できるもの)が必要。

1. Chrome で `https://notebook.google.com/` を開く(ログイン済みであること)
2. JavaScript で `window.fetch` と `XMLHttpRequest.prototype.send` を包み、`batchexecute` 宛てのリクエストを `window.__cap` に貯めるフックを仕掛ける
3. 画面で **1件だけ手でリネームする**(カードの「⋮」→「タイトルを編集」→ 保存)。本物のリクエストが `window.__cap` に入る。リネームの rpcid は `s0tc2d`
4. そのリクエストを雛形にし、本文中の **ノートブックID(UUID)** と **タイトル(`encodeURIComponent(タイトル)` の形)** の2か所だけ差し替えて送る関数を作る
   - 認証トークンは雛形に入ったまま送られる。**トークンの中身を読んだり、画面やファイルに書き出したりしない**
5. `{id, 新タイトル}` の配列でループする
   - 1件ごとに **400ms** 空ける
   - **1回 10件以内**に分け、まとまりの間は数分空ける(一気に流すと Google 側で詰まる)
   - 結果は `window.__results` に貯める

## 検証(送信結果を信じない)

200 / success が返っても反映されないことがある。**必ず読み取り側で取り直して ID 単位で突き合わせる。**

- 第一候補: `notebooklm list --json` を取り直して比べる
- CLI の認証が通らない時: `notebook.google.com` の画面から、カードのリンクの `href` にある UUID と、同じカード内の **`【` `】` を含む行**をタイトルとして対にする(カード先頭のアイコン絵文字は別要素なので、最初の行を取ると誤る)
- 共有されたノートブックは「共有アイテム」タブにある
- 「すべて」タブには Google のおすすめノートブックも混ざるので件数をうのみにしない

反映されていない ID があれば、追加で送る前に**もう一度読み直す**(遅れて反映されていることがある)。

## 変更できないもの

- **他人から共有されたノートブック(`is_owner: false`)は名前を変えられない**。API は success を返すが反映されない。対象から外し、再試行しない
- カード左上のアイコン絵文字は Google の自動生成で変えられない。識別はタイトル先頭の絵文字で行う

## CLI の状況(2026-09 時点)

| 操作 | コマンド | 状態 |
|---|---|---|
| 全件取得 | `notebooklm list --json` | 使える |
| リネーム | `notebooklm rename -n <id> "新タイトル"` | 効かない(偽の成功) |
| 削除 | `notebooklm delete -n <id>` | 実行後に必ず `list` で確認 |
| 認証チェック | `notebooklm auth check` | 当てにならない。確認は `list` で |

完了後の提案: 重複・似たノートブックの統合候補、使い終わったものに `📦【済】` を付ける運用。
